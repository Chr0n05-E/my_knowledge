# 二分查找

## 定义

在有序序列 $a_0 \le a_1 \le \dots \le a_{n-1}$ 中，用 $O(\log n)$ 次比较确定某个目标是否存在及其位置：每次取区间中点，用一次比较把候选区间**砍掉一半**。

推广形式（更常用、更不容易写错）：在谓词 $P$ 具有单调性（前段假、后段真）时，求第一个使 $P$ 为真的下标。

## 我的理解

二分查找的本质不是"折半"，而是**一次比较换一半候选集**。它成立的前提被人反复忽略：比较的结果必须能把你面前的可能性空间**切成两块**，并且这两块是"互斥且穷尽"的。有序性提供的就是这个切分能力。

我真正记住它，是靠**不变量（invariant）**而不是靠背代码：维护一个始终为真的命题，比如"答案一定在 $[lo, hi)$ 里"。每次循环都要做两件事——收缩区间、保持命题为真。这样边界是 $<$ 还是 $\le$、中点要不要 $+1$，全都由不变量推出来，不需要死记。

后来我才意识到这是**结构性的技能，不是知识点**：任何"单调性 + 可判定"的问题都能套（在旋转数组里找最小值、求平方根、答案二分/二分答案、求第 $k$ 小）。这属于我知识库里典型的"一个概念横向连出很多边"的节点。

## 直觉 / 为什么

顺序查找的代价是 $n$ 次比较。一个比较最多给出两种结果，也就是最多 $\log_2$ 比特信息；从 $n$ 个候选中区分出 1 个，需要的信息量下界就是 $\log_2 n$。所以 $O(\log n)$ 不是"技巧好"，而是**信息论下界**：顺序结构上不可能更快。这也解释了为什么哈希表（$O(1)$ 期望）不是违反这个下界——它换了一种结构，允许比较之外的随机访问。

## 关键结论

- 复杂度：$T(n) = T(n/2) + O(1) \Rightarrow T(n) = O(\log n)$，空间 $O(1)$（迭代版）。
- 用 $[lo, hi)$ 半开区间写，`while (lo < hi)`，`mid = lo + (hi - lo) / 2`（这样写还顺手躲开了整型溢出）。
- 求"第一个满足 $P$ 的位置"的模板：若 $P(mid)$ 为真则 `hi = mid`，否则 `lo = mid + 1`；循环结束后答案是 `lo`。
- 适用前提三条：**有序/单调**、**支持随机访问**、**比较代价可接受**。链表上做二分因为访问是 $O(n)$，总代价反而 $O(n)$。

## 边界与反例

- **重复元素**：朴素二分找到的是"某一个"相等的元素，不是第一个或最后一个。要边界必须用上面那个单调谓词模板（`lower_bound` / `upper_bound`）。
- **浮点二分**：不要用 `lo < hi` 当终止条件，要用固定的迭代次数（如 100 次）或精度阈值，否则可能死循环。
- **中点写错**：`mid = (lo + hi) / 2` 在 `lo + hi` 溢出时会得到负数，C++/Java 里这是经典 bug。
- **直觉陷阱**：以为"有序"是必要条件。其实只要谓词单调就行——"答案二分"里数组根本不需要有序。

## C++ / 两数之和：提交两种实现

约 11:41—14:18，在「哈希表优化两数之和」中学习。

- 提交双层循环穷举版，跳过 `i == j`，找到目标后返回索引；主动询问哈希表能否降低时间复杂度。
- 要求先理解 `unordered_map` 的本质，再自己实现。
- 正确回答补数为 `target - nums[i]`；key 存数值，value 存数组索引。
- 明确困惑：迭代器、`auto`、`first` / `second`。曾误以为 first 与 second 对应当前位置与下一目标；随后回答练习并指出查找不到时返回 `end()`。
- 14:18 提交一次遍历的哈希表实现，使用 `find(need)`，找到后返回 `{i, it->second}`，否则存入当前数值和索引。该实现作为实际产出保留如下。

```cpp
class Solution {
public:
    vector<int> twoSum(vector<int>& nums, int target) {
        unordered_map<int,int> mp;
        for(int i=0;i<nums.size();i++){
            int need=target-nums[i];
            auto it=mp.find(need);
            if(it!=mp.end()){
                return {i,it->second};
            }
            else{
                mp[nums[i]]=i;
            }
        }
        return {};
    }
};
```

### 助手补充的复习要点（不算用户已掌握）

| 解法 | 时间 | 额外空间 | 需要理解的取舍 |
|---|---|---|---|
| 穷举 | 最坏 O(n²) | O(1) | 简单，当前双循环会重复考察两个方向的同一对 |
| unordered_map | 平均 O(n)，最坏 O(n²) | O(n) | 用空间换查找效率；不是无条件最坏 O(n) |
| 排序后双指针 | O(n log n) | 视实现而定；保留原索引的复制方案 O(n) | 原题返回索引，需要保留索引映射；已排序输入的扫描可 O(n) |

待复核：为什么先查再插能防止同一元素被重复使用；`first` / `second` 是键值对成员；`auto` 是类型推导；`end()` 是不可解引用的结束位置。

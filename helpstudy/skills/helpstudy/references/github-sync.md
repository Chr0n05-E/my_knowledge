# GitHub读取、记录与并发更新

固定目标：`Chr0n05-E/my_knowledge`，main。按实际可用能力选择一种路径；不要猜测接口签名、编造文件SHA或创建凭据。

## 有本机或云端Git工作区

核对origin、当前分支、未提交内容、暂存区与进行中的Git操作。先fetch，查看本地与origin/main的新增提交和变化，再同步。干净且可快进时使用ff-only；已有未提交或未发布内容、分叉时保留并报告，不能reset、stash或force push。同步后重新读取学习档案。

已确认的Windows知识库可用仓库内 `tools/sync-study.ps1 -Mode Before` 与 `-Mode After -Message 'study: 描述实际进展'`。先查看当前脚本及调用约定，再执行；普通学习同步默认仅提交helpstudy。其他系统不要假定PowerShell已安装，按同等步骤操作Git即可；新克隆可用常规git clone，不能覆盖既有目录。

结束时检查diff，仅选本次学习相关文件提交，不混入其他任务修改。提交后再fetch；若另端已发布新内容且工作区干净，可rebase自己的学习提交后重试推送。冲突时abort，保留本地提交，报告冲突文件及未发布状态。最多3次推送尝试，不强推；网络或认证失败不无限重试。没有变化不制造空提交。

推送成功报告实际提交链接；若无法再次读取远端确认，说明已知验证范围，不声称已经得到额外确认。

## 有GitHub连接/API，没有工作区

首先检查连接实际提供的读、写及提交/PR工具。明确获取main当前提交以及目标文件正文和版本标识，而不是只搜索仓库描述。读取最近学习文件后再辅导。优先使用当前连接的直接工具，公开读取可回退到raw页面；搜索或缓存页面须注明时效范围。

写入前重新获取main与每个将修改文件的当前内容，核对自开始以来是否变化。若变化，基于新内容重新合并自己的学习小段，保留双方；不能把旧快照整份覆盖。优先采用能将多文件作为一个提交并检查基准提交的工具。若接口需要SHA或预期版本，使用实际读取值。不要虚构原子性；工具只能逐文件写时，按实际结果报告哪些已发布、哪些未发布，后续重新读取修复一致性。

出现SHA过期或非快进拒绝时重新读取并合并，最多3次；冲突无法明确整合时停止该写入、保留待提交记录并说明。实际成功后拿到提交链接。仅有PR能力时建立PR，在受支持的本机Codex环境按要求附到当前任务；不要自动合并，不声称main已更新。也不要为每次学习强行要求PR，如果已有直接提交能力且用户授权直接发布可直接使用。

## 只能阅读，或仓库暂时不可访问

仍可根据实际已读档案辅导。无法获取时明确最后已知日期及缺失内容；用户的当前反馈优先。不声称自动写回。结束时交付一段可复制的待同步记录：学习日期、主题、用户实际输出、理解变化、未解决问题、后续建议、目标文件与未发布状态。有可下载文件能力时可提供记录文件；写权限恢复后重新读取最新版本再提交。

公开仓库的读取与当前会话GitHub写权限是两件事。本技能不附带账户凭据或额外授权，也不自动开通连接。

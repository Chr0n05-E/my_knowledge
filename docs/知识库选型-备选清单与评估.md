## 1. 先分清你在选什么：四层，别混在一起选

大多数选型失败是因为把四件独立的事当成一件：

| 层 | 你要选的是 | 换了会怎样 |
|---|---|---|
| **① 内容载体**（数据层） | 笔记以什么形式存在磁盘上：纯 Markdown 文件 / 数据库 / 私有格式 | 决定**退出成本**。这层选错，后面全都白做 |
| **② 结构约定**（结构层） | 层级怎么表达（目录？frontmatter 属性？文件名？）、关联怎么表达（双链？属性？） | 决定**你十年后还能不能在自己库里找到东西**。这层跟软件弱相关，是习惯 |
| **③ 前台**（写作层） | 你每天打字用的那个软件 | **最容易换**，也是最容易纠结的。它只影响手感 |
| **④ 视图**（呈现层） | 图谱、思维导图、目录页、发布站点、AI 问答 | **全部是可以随时重算的派生物**。不是资产 |

**如果只记一句：①②是资产，③④是耗材。** 因此评估时，把"导出能力"和"数据格式"的权重放得比"图谱好不好看"高一个量级——这也是本文第 2 节权重表的由来。

## 2. 评估维度（含建议权重，你可以改）

| # | 维度 | 建议权重 | 要看什么 / 怎么测 |
|---|---|---|---|
| 1 | **数据主权与退出成本** | ★★★★★ | 磁盘上是纯文本还是私有格式；导出是否**无损**（双链、属性、附件、历史）；导出的东西能否被别的软件直接读 |
| 2 | **结构表达力** | ★★★★★ | 层级深度是否受限；**能否一个概念挂两个父节点**（数学↔理学、CS↔数学）；是否支持属性 + 查询（自动生成目录页）；双链别名归一（`[[素数定理]]`/`[[PNT]]` 指同一节点） |
| 3 | **长期可持续性** | ★★★★☆ | 最近 6 个月是否有提交/发版；治理结构（公司/个人/社区）；**有没有改许可证的前科**（改许可、被收购 = 高危信号）；参考本年度的 Kùzu、Dendron、Reor |
| 4 | **中文支持** | ★★★★☆ | 界面语言、中文文档与社区、中文排版（标点挤压/字体）、中文搜索分词 |
| 5 | **多设备与同步** | ★★★☆☆ | 有没有手机端；同步是官方服务、自建还是 Git；冲突怎么处理；离线可用性 |
| 6 | **写作体验** | ★★★★☆ | 输入流畅度、公式（LaTeX）、表格、图片粘贴、块引用/大纲、搜索速度 |
| 7 | **视图能力** | ★★★☆☆ | 全局/局部图谱、思维导图、目录页自动生成、时间线 |
| 8 | **扩展性与可编程** | ★★★☆☆ | 插件生态；能否脚本化（CLI/API）；**能否长成你自己想要的形状** |
| 9 | **上手与迁移成本** | ★★★☆☆ | 用多久能顺手；是否需要写代码/跑服务；把现有笔记搬进去要几天 |
| 10 | **成本** | ★★☆☆☆ | 免费/订阅/一次性；自建的隐性成本（运维时间才是真的贵） |
| 11 | **检索与 AI** | ★★☆☆☆ | 全文检索质量、语义检索、本地 LLM、能否叠加第三方 RAG |

> 用法建议：先按上表把权重改成你自己的（比如你不在乎手机端就把 5 降到 ★），再去看第 4、5 节的候选——**权重不同，最优解会直接翻盘**。

## 3. 五条架构路线（先选路线，再选软件）

这一步比选软件重要：下面每条路线的**退出成本差一个数量级**。

### 路线 A：现成客户端当一体机
- **形态**：装一个软件，内容 + 结构 + 视图都在它里面。
- **代表**：Obsidian、思源笔记、TriliumNext。
- **优点**：十天可用，视图开箱即有（图谱、目录树、搜索）。
- **代价**：内容形态取决于软件（Obsidian 是纯 MD，思源是 `.sy` JSON，Trilium 是 SQLite）；结构（属性名、查询语法）会带有该软件的印记。
- **适合**：想**尽快开始写**、不打算自己写代码的人。

### 路线 B：纯文本库 + 自建视图
- **形态**：`notes/` 里全是 Markdown + frontmatter，自己（或脚本）生成图谱与思维导图。
- **代表**：本机 `E:\Knowledge` 这套骨架；Foam（VS Code）；以及任何「Markdown + 脚本」组合。
- **优点**：退出成本≈0；视图可以随便换（markmap、Cytoscape、Obsidian、Gephi 都能读）；结构完全由你定。
- **代价**：**你要维护脚本**；没有手机端；写作体验取决于你选的编辑器（VS Code 不如专用软件顺手）。
- **适合**：愿意写一点脚本、把"数据主权"和"结构自定义"排在最前面的人。

### 路线 C：大纲/属性驱动
- **形态**：以"块"和属性为一等公民，层级由 namespace/属性推导。
- **代表**：Logseq、Emacs org-roam、Tana（商业）。
- **优点**：非层级关联最自然；查询能力最强（Datalog / org-ql）。
- **代价**：**与"文件即资产"冲突**（Logseq 2.0 已转数据库；org-roam 需要你活在 Emacs 里）；层级树是二等公民。
- **适合**：思考方式本来就是"每天记一条、之后自己长出来"，而不是"先建分类树"的人。

### 路线 D：自建/发布式站点
- **形态**：笔记在文件里，另外跑一个服务或用静态生成器发布成站点。
- **代表**：Quartz、Flowershow、Wiki.js、MediaWiki + Semantic MediaWiki、Wikibase。
- **优点**：对外可读、可分享、全文检索与权限完善；语义 Wiki 的查询能力极强。
- **代价**：**要跑服务 / 维护部署**；个人单机用往往是"为了一个视图背上一台服务器"。
- **适合**：确实要给人看（数字花园、课程、团队），或者你需要 SPARQL 式的语义查询。

### 路线 E：图数据库 / 图谱引擎驱动
- **形态**：把节点和边灌进数据库（Neo4j / Oxigraph / LadybugDB），前端查询渲染。
- **代表**：Neo4j 社区版、Oxigraph、LadybugDB；LLM 抽取层 GraphRAG / Graphiti / LightRAG。
- **优点**：多跳查询、聚合提问、作为服务暴露给别的程序。
- **代价**：**多一个真相源**（笔记与库必然不一致）、常驻服务、备份与 schema 迁移、许可证坑（Neo4j 社区版 GPL-3.0、Memgraph/ArangoDB 是 source-available 非 OSI 开源）。而且本年度 **Kùzu 已归档**，正是"押注小众图库"的风险样本。
- **判断**：几百到几千条笔记**不需要**它——全量重建是秒级，"派生物永远重算"这条策略成立，而图数据库的价值前提恰恰是"全量重建太贵，必须增量维护"。
- **适合**：笔记进入数万条且日常做多跳查询；或要把图谱作为服务给 agent/网站用。

### 交叉层（不是路线，是可以后加的）
- **AI 检索层**：Khoj、AnythingLLM 等，叠加在路线 A/B 之上做自然语言提问。
- **记忆层**：Anki / FSRS 间隔重复，与叶子节点联动。
- **检索层**：全文检索（ripgrep、Obsidian 搜索）、语义检索（本地嵌入模型）。

> **组合是常态**：路线 A（Obsidian 写作）+ 路线 B（脚本生成图谱/大纲）+ 交叉层（Khoj）= 很常见且合理的配置。选型时不要以为只能选一个。

## 6. 决策树：回答几个问题就能收敛

按顺序回答，遇到"是"就停在对应建议上先做试点：

| # | 问题 | 回答"是" | 回答"否" |
|---|---|---|---|
| 1 | 你要求笔记在磁盘上就是**能被任意工具打开的纯文本**吗？ | 进 2 | 进 5 |
| 2 | 你**愿意为它写一点脚本或做点配置**吗？ | 路线 B（纯文本 + 自建视图）；前台可选 Obsidian/VS Code | 进 3 |
| 3 | 你能接受**闭源但免费、本地**的软件吗？ | **Obsidian**（当前综合最优解，纯 MD + 图谱 + 插件） | 进 4 |
| 4 | 中文体验与块级引用优先，且能接受私有格式？ | **思源 SiYuan** | **TriliumNext**（数据模型天生是树） |
| 5 | 你的思考方式本来就是"先记一条条，分类后长出来"？ | **Logseq** 或 **org-roam**（路线 C） | 进 6 |
| 6 | 你需要**把知识库当站点对外发布**，或有语义查询需求？ | 路线 D（Quartz / Wiki.js / MediaWiki+SMW） | 进 7 |
| 7 | 你的笔记预计会到**上万条**，且日常要做多跳查询？ | 路线 E（图数据库）——先读第 3 节的风险 | **回到 1**：你其实要的是视图，不是数据库 |

补充三个独立开关（与上面正交，可以后加）：
- 要**手机上看/写** → 排除纯自建脚本路线，倾向 Obsidian（官方 Sync 付费）或思源；
- 要**AI 问答** → 在选定前台之上叠加 Khoj/AnythingLLM，不必改变主库；
- 公式密度高（你的数学分支）→ 把"LaTeX 渲染质量"当作硬指标，Obsidian/思源/VS Code 都能打，但要实测输入手感。

## 7. 试错与止损：怎么在不浪费时间的前提下选

**核心原则：先做一次"两周小试点"，然后再决定要不要迁移全部笔记。**

### 7.1 试点动作（每个候选都跑一遍，半天到两天）

| 测试 | 为什么关键 |
|---|---|
| 建 **1 个多父节点**（如"线性代数"同时挂"代数"和"计算机科学"） | 检验结构表达力——这是你需求里最容易卡住的地方 |
| 写 **1 条含 3 个公式的笔记**（行内 + 独立成行） | 数学分支的硬指标，也要测输入手感 |
| 插 **1 张本地图片** | 书法/美学分支必须有 |
| 从 5 个不同入口**搜同一个概念**（标题、别名、标签、正文、拼音） | 检索决定十年后的可用性 |
| **导出全部**，再用另一个软件打开导出的东西 | 唯一能验证"退出成本"的动作，别信宣传页 |
| 在**手机**上打开并改一个字 | 同步与冲突的真实体验 |
| 用 **git diff** 看一次改动 | 纯文本路线的最大红利：能版本化、能看清自己改了什么 |
| 删除候选 | 两周后留 1 个，其他删掉。**不删就会一直纠结** |

### 7.2 三条"无论选谁"的硬规则（防止十年后被锁死）

1. **原始内容保持纯文本**——若软件用私有格式（思源 `.sy`、Trilium SQLite），就设一个**每周自动导出到 Markdown + git** 的任务，导出目录也算资产；
2. **结构必须可导出**——层级与关联不能只活在该软件的数据库里；至少要能导出成「一行一条边」的表格或 JSON；
3. **每季度做一次"这个软件明天死掉"演练**：导出 → 换一个工具打开 → 能不能找到东西。做不到就说明你在依赖它的数据库，而不是你自己的笔记。

> 参考：本年度 Kùzu 归档、Dendron 停更、Reor 归档、Juggl 插件停在 2022——**"现在很火"不构成长期保证**，能带走的资产才是保证。

## 8. 需要你回答的问题（回答完我可以收敛到 2–3 个最终候选）

1. **数据主权**：你要求磁盘上是纯 Markdown 文件（能被 grep/其他编辑器直接读），还是可以接受软件自己的数据库格式（只要导出方便）？
2. **代码意愿**：你愿意为知识库写/维护一点脚本（Python/JS）或跑一个本地服务吗？还是希望"装完就能用，永不碰命令行"？
3. **设备**：需要手机端吗？多设备同步你倾向「官方付费同步」「自建/Git」「只在一台电脑上」哪种？
4. **量级与增长**：预计最终多少条笔记（几百 / 几千 / 上万）？增长是"每天几条"还是"集中整理"？
5. **发布**：需要对外发布（数字花园/博客/给人看的站点）吗？
6. **AI**：需要自然语言问答/语义检索吗？愿意用本地模型还是接受 API key？
7. **软件许可偏好**：只接受开源，还是"闭源但免费且本地"也可以？
8. **现有材料**：你已经有笔记/大纲/思维导图文件需要迁移吗？大概什么格式、多少量？
